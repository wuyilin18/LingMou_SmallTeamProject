# 灵眸（LingMou）项目设计方案

> **项目名称：** 灵眸------基于多模态感知的桌面具身智能交互系统\
> **英文名称：** LingMou: A Multimodal Desktop Embodied Interactive
> System\
> **项目定位：** 集拟态视觉表达、姿态感知、环境感知、BLE/WiFi
> 双通道通信与移动端控制于一体的桌面智能交互终端\
> **核心平台：** ESP32-C6 + 1.47 英寸 LCD + MPU6050 + AHT20 + Uni-app
> 移动端\
> **当前版本依据：** `LingMou.ino`、`index.vue`

------------------------------------------------------------------------

## 1. 项目概述

### 1.1 项目背景

传统桌面电子设备通常以数据显示、按键控制或固定动画为主要交互方式，设备能够"显示信息"，但缺少对环境、姿态和用户操作的综合感知，也缺乏具有生命感的视觉反馈。

"灵眸（LingMou）"项目以 ESP32-C6 为核心控制器，通过 LCD
拟态眼睛作为主要视觉载体，将姿态传感器、温湿度传感器、BLE、WiFi、移动端
App
和表情行为引擎进行融合，使设备不仅能够显示信息，还能够根据自身姿态、外界扰动以及用户指令产生凝视、眨眼、情绪变化等行为，从而形成具有"感知---决策---表达---反馈"闭环的小型桌面具身交互系统。

项目强调低成本、轻量化、本地实时响应和可扩展性，可作为智能桌宠、交互式
IoT
终端、嵌入式教学平台以及后续接入语音、大模型和更多传感器的具身智能原型平台。

------------------------------------------------------------------------

## 2. 项目目标

### 2.1 总体目标

设计并实现一套以 ESP32-C6 为核心的桌面智能交互终端，实现：

1.  通过 LCD 显示具有生命感的拟态双眼；
2.  支持多种情绪、眨眼、凝视和随机行为；
3.  感知设备姿态、运动和突然扰动；
4.  实时采集环境温度与湿度；
5.  通过 BLE 与手机 App 建立近距离控制通道；
6.  通过 BLE 完成 WiFi 首次配网；
7.  WiFi 联网后提供 HTTP 数据接口；
8.  支持 BLE/WiFi 双通道遥测与自动回退；
9.  在设备端提供"眼睛模式"和"信息模式"；
10. 在移动端形成统一的 LingMou 控制中心。

### 2.2 设计原则

-   **实时性：** 眼睛动画和姿态响应应保持流畅。
-   **鲁棒性：** 单个传感器或网络异常不应导致核心系统完全失效。
-   **低耦合：** 显示、传感、通信和移动端控制模块相对独立。
-   **可扩展：** 为语音、AI、大模型、更多传感器和云端能力预留接口。
-   **低门槛：** 尽量使用成熟开源库和常见硬件。
-   **双通道：** BLE 负责发现、控制和兜底，WiFi 负责局域网增强通信。

## 3. 系统总体架构

系统采用"感知层---控制层---通信层---表现层---应用层"五层结构。

``` text
┌──────────────────────────────────────────────┐
│                移动端应用层                   │
│        Uni-app / LingMou Control App          │
│  表情控制 / 凝视控制 / WiFi配网 / 环境数据     │
└──────────────────────┬───────────────────────┘
                       │
              BLE       │       WiFi/HTTP
                       │
┌──────────────────────▼───────────────────────┐
│                  通信层                       │
│ NimBLE GATT / WiFi STA / WebServer / NTP      │
└──────────────────────┬───────────────────────┘
                       │
┌──────────────────────▼───────────────────────┐
│                  控制层                       │
│                 ESP32-C6                      │
│ 状态管理 / 指令解析 / 行为控制 / 定时任务       │
└───────────────┬────────────────┬─────────────┘
                │                │
┌───────────────▼──────┐  ┌──────▼────────────┐
│       感知层          │  │      表现层        │
│ MPU6050 姿态/运动     │  │ ST7789 LCD         │
│ AHT20 温湿度          │  │ 拟态眼睛 / 信息界面 │
└──────────────────────┘  └───────────────────┘
```

### 3.1 核心数据闭环

``` text
环境/姿态变化
     ↓
AHT20 / MPU6050
     ↓
ESP32-C6 数据采集
     ↓
状态判断与行为逻辑
     ↓
Face 表情/凝视引擎
     ↓
LCD 视觉表达
     ↓
BLE/WiFi 遥测
     ↓
手机 App 状态展示
     ↓
用户控制指令
     └────────────→ ESP32-C6
```

由此形成完整的：

**感知 → 状态判断 → 行为生成 → 视觉表达 → 通信反馈 → 用户干预**

交互闭环。

## 4. 硬件设计

### 4.1 主控制器

系统采用 **ESP32-C6** 作为核心控制器。

主要承担：

-   LCD 图形输出；
-   I2C 传感器数据采集；
-   BLE GATT 服务；
-   WiFi STA 联网；
-   HTTP API 服务；
-   NTP 网络授时；
-   行为状态管理；
-   App 指令解析；
-   NVS 参数持久化。

ESP32-C6
同时具备无线通信和较强的嵌入式处理能力，可减少额外通信模块，降低系统体积和复杂度。

### 4.2 显示模块

当前硬件采用 Waveshare ESP32-C6-LCD-1.47 平台对应的 ST7789 LCD：

-   分辨率：172 × 320；
-   SPI 通信；
-   Arduino_GFX 负责实际 LCD 输出；
-   TFT_eSPI 的 Sprite 用作眼睛图形离屏缓冲。

当前关键引脚：

  功能              GPIO
  --------------- ------
  LCD MOSI             6
  LCD SCLK             7
  LCD CS              14
  LCD DC              15
  LCD RST             21
  LCD Backlight       22
  SD CS                4

采用"Sprite 离屏绘制 + Arduino_GFX
输出"的方式，可减少复杂动画直接刷新屏幕产生的闪烁。

### 4.3 姿态感知模块

采用 **MPU6050** 六轴惯性传感器。

主要用途：

-   获取三轴加速度；
-   判断设备倾斜方向；
-   将倾斜映射为眼球凝视方向；
-   检测突然加速、晃动或冲击；
-   触发 Scared 等情绪反馈。

I2C 引脚：

  功能     GPIO
  ------ ------
  SDA        18
  SCL        19

当前软件配置包括：

-   加速度范围：±2 g；
-   滤波带宽：21 Hz；
-   I2C 时钟：100 kHz。

### 4.4 环境感知模块

采用 **AHT20** 温湿度传感器。

主要采集：

-   环境温度；
-   环境相对湿度。

当前默认每约 3 秒进行一次传感器读取，并将数据用于：

1.  设备信息模式显示；
2.  BLE 遥测；
3.  WiFi HTTP API；
4.  App 环境信息页面。

### 4.5 物理按键

GPIO 9 配置为模式切换按键，采用内部上拉和下降沿中断。

功能：

``` text
按键触发
   ↓
MODE_EYE ↔ MODE_INFO
```

软件设置约 300 ms 防抖时间。

### 4.6 建议 BOM

  模块     器件               作用
  -------- ------------------ --------------------
  主控     ESP32-C6           系统控制与无线通信
  显示     ST7789 LCD         拟态眼睛和信息显示
  IMU      MPU6050            姿态与运动感知
  温湿度   AHT20              环境感知
  按键     轻触按键           模式切换
  电源     USB/5V 电源模块    系统供电
  外壳     3D 打印/定制外壳   产品化封装

## 6. 拟态眼睛与情绪系统

### 6.1 眼睛引擎

系统通过 `LingMouEngine` 中的 Face 行为引擎管理眼睛。

核心能力包括：

-   自动眨眼；
-   手动眨眼；
-   凝视位置控制；
-   随机凝视；
-   随机行为；
-   情绪切换；
-   姿态驱动凝视；
-   冲击触发情绪。

当前眼睛动画目标刷新周期约为：

``` text
33 ms / frame ≈ 30 FPS
```

能够满足小尺寸 LCD 上的基本流畅动画要求。

### 6.2 情绪集合

当前移动端定义 18 种情绪：

    序号 情绪
  ------ -------------
       0 Normal
       1 Angry
       2 Glee
       3 Happy
       4 Sad
       5 Worried
       6 Focused
       7 Annoyed
       8 Surprised
       9 Skeptic
      10 Frustrated
      11 Unimpressed
      12 Sleepy
      13 Suspicious
      14 Squint
      15 Furious
      16 Scared
      17 Awe

### 6.3 姿态驱动凝视

MPU6050 的 X/Y 加速度经过比例换算后映射至：

``` text
look_x ∈ [-1, 1]
look_y ∈ [-1, 1]
```

从而实现：

``` text
设备向左倾斜 → 眼睛产生对应方向凝视
设备向右倾斜 → 眼睛产生对应方向凝视
设备前后倾斜 → 眼睛上下移动
```

该机制让眼睛表现与实体设备姿态建立联系，是项目"具身感"的重要来源。

### 6.4 扰动情绪响应

系统计算总加速度：

``` text
A = √(ax² + ay² + az²)
```

当总加速度与重力加速度偏差超过设定阈值时，认为设备发生明显晃动或冲击，并进入
`Scared` 状态。

当前逻辑约保持 1.5 秒后恢复 Normal。

这一机制形成：

``` text
物理扰动
  ↓
MPU6050
  ↓
异常加速度检测
  ↓
Scared 情绪
  ↓
LCD 视觉反馈
```

使用户对实体设备的动作能够直接影响虚拟表情。

## 8. BLE 通信设计

### 8.1 BLE 服务

设备名称：

``` text
LingMou
```

Service UUID：

``` text
4fafc201-1fb5-459e-8fcc-c5c9c331914b
```

RX Characteristic：

``` text
beb5483e-36e1-4688-b7f5-ea07361b26a8
```

TX Characteristic：

``` text
beb5483e-36e1-4688-b7f5-ea07361b26a9
```

通信方向：

``` text
App → RX → ESP32-C6
ESP32-C6 → TX Notify → App
```

### 8.2 控制协议

当前采用轻量文本协议。

  指令        示例              功能
  ----------- ----------------- -------------------
  眨眼        `B:1`             执行一次眨眼
  随机行为    `I:1`             开启随机行为
  随机凝视    `W:1`             开启随机凝视
  情绪        `E:3`             切换至对应情绪
  凝视        `X:0.5,-0.3`      设置眼睛 X/Y 方向
  获取状态    `GET_STATUS`      返回设备状态
  获取遥测    `GET_TELEMETRY`   返回环境数据
  手机授时    `TIME=<epoch>`    同步系统时间
  WiFi SSID   `WIFI_SSID=xxx`   设置 WiFi 名称
  WiFi 密码   `WIFI_PASS=xxx`   设置密码
  开始联网    `WIFI_CONNECT`    保存并连接 WiFi
  清除网络    `WIFI_CLEAR`      清除 WiFi 配置

### 8.3 BLE 分片机制

BLE 默认 ATT MTU 较小时，单次 Notify 可传输的数据有限。

当前固件根据 Peer MTU 自动计算分片大小，App
端对连续数据进行重新拼接，可降低 JSON 状态消息因 MTU
不足而被截断的风险。

WiFi SSID 和密码同样支持分片发送，例如：

``` text
WIFI_SSID=
WIFI_SSID+
WIFI_PASS=
WIFI_PASS+
```

适配较长网络名称和密码。

### 8.4 BLE 看门狗

设备在 BLE 断开后持续检查实际广播状态。

若发现广播停止：

``` text
未连接 + 未广播
       ↓
BLE Watchdog
       ↓
重新启动 Advertising
```

提高 App 再连接成功率。

## 9. WiFi 与网络设计

### 9.1 BLE 辅助配网

首次使用时，设备不需要预写 WiFi 信息。

流程：

``` text
App 扫描 LingMou
      ↓
建立 BLE
      ↓
输入 SSID / Password
      ↓
BLE 分片发送
      ↓
ESP32-C6 保存至 NVS
      ↓
WiFi STA 发起连接
      ↓
设备返回连接结果/IP
```

### 9.2 NVS 持久化

WiFi 信息通过 ESP32 `Preferences` 保存至 NVS。

设备重新上电后：

``` text
读取 NVS
   ↓
存在 WiFi 信息
   ↓
自动连接
```

用户无需每次重新配网。

### 9.3 自动重连

当前系统设计：

-   单次连接超时约 15 秒；
-   失败后延迟约 30 秒再次尝试；
-   WiFi 使用自动重连；
-   WiFi 不可用时 BLE 仍保持工作。

### 9.4 HTTP API

WiFi 成功后，设备启动本地 WebServer，端口为 80。

当前接口：

``` text
GET /api/status
GET /api/telemetry
```

#### `/api/telemetry`

典型响应：

``` json
{
  "t": 25.6,
  "h": 48.3,
  "aht": 1,
  "time": "14:32:18",
  "wifi": 1
}
```

#### `/api/status`

返回内容包含：

-   WiFi 是否连接；
-   是否正在连接；
-   BLE 状态；
-   SSID；
-   IP 地址；
-   当前遥测数据。

### 9.5 双通道策略

项目采用：

**BLE 基础通道 + WiFi 增强通道**

``` text
             ┌─ WiFi HTTP ─ 高效遥测
App ─ LingMou┤
             └─ BLE ─ 控制 / 配网 / 兜底
```

WiFi HTTP 不可达时，App 可继续使用 BLE
接收遥测信息，不因局域网问题失去核心控制能力。

## 10. 时间同步设计

系统支持两种授时方式。

### 10.1 手机 BLE 授时

App 在 BLE 建立连接后发送：

``` text
TIME=<Unix Timestamp>
```

ESP32-C6 设置本地系统时间。

### 10.2 NTP 授时

WiFi 连接成功后，通过：

``` text
pool.ntp.org
```

进行网络时间同步。

当前时区按照 UTC+8 进行显示。

因此设备可形成：

``` text
无 WiFi → 手机 BLE 授时
有 WiFi → NTP 自动校时
```

## 12. 系统状态与任务调度

当前固件采用 Arduino `loop()` 非阻塞式周期调度。

主要任务包括：

  任务            周期/触发
  --------------- -----------
  眼睛动画        约 33 ms
  AHT20 读取      约 3 s
  Info 界面刷新   约 1 s
  NTP 更新        约 30 s
  BLE 广播检查    约 2 s
  WiFi 重试       约 30 s
  按键模式切换    中断触发

总体原则是：

**尽量避免长时间阻塞，使动画、通信和传感器任务能够并行推进。**

## 13. 可靠性设计

### 13.1 传感器故障降级

MPU6050 初始化失败：

``` text
保留眼睛显示、BLE、WiFi、AHT20
仅关闭姿态功能
```

AHT20 初始化失败：

``` text
保留眼睛、姿态、BLE、WiFi
温湿度显示为不可用
```

体现模块化故障隔离思想。

### 13.2 网络故障降级

``` text
WiFi 异常
   ↓
HTTP 遥测不可用
   ↓
BLE 继续工作
   ↓
控制与基础遥测不中断
```

### 13.3 BLE 断线恢复

通过广播看门狗保证设备断开后重新进入可发现状态。

### 13.4 显示刷新控制

眼睛动画采用局部 Sprite 输出，信息模式采用低频刷新，减少 LCD
闪烁和无效刷新。

## 14. 当前项目创新点

### 14.1 多模态感知与拟态表达融合

项目不是单纯的电子眼动画，而是将：

-   姿态；
-   运动；
-   环境温度；
-   环境湿度；
-   用户控制；
-   网络状态

统一接入交互系统。

### 14.2 实体姿态与虚拟凝视联动

设备物理倾斜能够改变虚拟眼睛凝视方向，使虚拟角色行为与实体载体建立直接联系，增强具身感。

### 14.3 物理扰动触发情绪

通过 IMU 判断明显扰动并触发 Scared
情绪，实现"外界刺激---内部状态---表情反馈"的轻量行为闭环。

### 14.4 BLE + WiFi 双通信架构

BLE 不仅承担控制，还承担首次 WiFi 配网和网络异常兜底；WiFi 则承担局域网
HTTP 数据传输。

相较于仅 BLE 或仅 WiFi 的设计，使用场景更加完整。

### 14.5 双模式终端

同一设备兼具：

-   情感交互终端；
-   环境信息终端。

通过物理按键在 Eye Mode 和 Info Mode 之间切换，提高硬件利用率。

### 14.6 可扩展的具身智能原型

当前系统已经具备：

``` text
Sensor → Perception → Behavior → Expression → Communication
```

基础闭环，可继续扩展 AI 推理和自主行为模块。

### 16.3 第三阶段：AI 能力

``` text

     ↓

     ↓
```

## 22. 项目特色总结

LingMou
的核心价值不在于单一硬件或单一动画，而在于构建了一个完整的小型交互闭环：

``` text
          ┌──────── Environment ────────┐
          │                              │
          ▼                              │
     Sensors                             │
 MPU6050 + AHT20                         │
          │                              │
          ▼                              │
      ESP32-C6                           │
          │                              │
    ┌─────┼────────┐                     │
    ▼     ▼        ▼                     │
Behavior Display Communication           │
    │     │        │                     │
    ▼     ▼        ▼                     │
 Emotion Eyes   BLE / WiFi               │
                 │                       │
                 ▼                       │
              Mobile App ────────────────┘
```

当前版本已经完成从"电子眼动画"向"多模态桌面交互终端"的转变。

项目后续最值得发展的方向不是继续简单堆叠更多动画，而是在现有硬件闭环基础上加入：

**声音感知 + 内部状态 + 自主行为 + AI 决策**

最终形成：

> **能感知环境、理解用户、产生状态、主动表达，并具有持续人格表现的桌面具身智能伙伴。**
